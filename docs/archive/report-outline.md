# 발표·리포트 아웃라인

한 줄: **에너지 설비의 알람을, 근거 있는 다음 점검으로.**

System 1이 추세와 현장 신고를 계속 살피며 조사할 사건을 고르고, System 2가 Nemotron과 읽기 전용 도구로 해당 사건을 조사해 엔지니어에게 출처가 있는 다음 확인 항목을 건넨다. 현재는 **System 2 공개 데이터 POC 한 건만 실행**했다.

## 1. 왜 중요한가

발전소에서 중요한 시간은 고장 후 **올바른 문제를 식별해 대응을 시작하기까지** 걸린 시간이다. 별도 Plant Economics Bench는 식별 시점이 몇 시간 뒤 → 30분 → 고장 순간 → 고장 전으로 이동할 때 회복 가능한 MWh와 가치를 가정별로 계산한다. 이는 기회 규모를 보여주는 시나리오이며 현재 POC가 입증한 절감액이 아니다. 비공개 사건 원문과 설비 식별자는 해커톤 자료에 옮기지 않는다.

## 2. 두 가지 속도

- **System 1 — 감시·선별:** 시간 순서가 맞는 계측값, 기존 알람, 현장 신고를 사내에서 수집한다. 데이터 품질을 확인하고 이상 후보를 만든 뒤, 정형 결정 단계에서 중복·우선순위·심층 조사 필요성을 판단한다. 규칙 기반 선별을 기준선으로 삼고 시계열 모델은 오탐이 감당 가능한 수준에서 조기 탐지가 개선될 때 채택한다.
- **작은 Nemotron — 정형 판단:** `Ultra로 올릴까?`, `신고와 계측이 충돌하는가?`, `어떤 근거가 부족한가?`처럼 범위가 좁은 질문을 Nemotron Nano 또는 규칙으로 처리한다. [Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev)는 이런 빠른 결정 모델의 설계 영감이며 **별도 API 연동 계획은 아니다**. 반환 형식은 코드가 검사하고, 판단의 정확도·불확실성은 별도로 평가한다.
- **System 2 — 심층 조사:** 선택된 사건에만 Nemotron Ultra를 호출한다. 계측 추세, 과거 사건, 문서, 경제성 도구를 읽기 전용으로 조회해 충돌과 결측을 표시하고, 사람이 검토할 점검 순서를 작성한다. Ultra의 높은 지능은 실험 가설이지 진단 정확도 보증이 아니다.
- **사람에게 전달:** System 1이 왜 올렸는지, System 2가 무엇을 읽었는지, 엔지니어가 무엇을 승인·수정했는지를 같은 사건 ID로 남긴다.

## 3. 화면에서 보여줄 사건

[PreDist 공개 POC](poc-result.md)에서는 고객이 난방 불량을 신고했지만 설비의 2차측 공급온도는 설정값을 따랐다. Ultra는 계측과 과거 이력을 조회하고 고객 측에서 확인할 값을 제안했다. [시각 데모](visual-demo.md)에서는 온도 센서 bbox를 클릭해 관측 근거를 보고, 고객 측 점선 bbox를 클릭해 아직 없는 측정값을 확인한다. 이 사례는 **센서가 정상처럼 보여도 현장 신고가 조사 대상이 될 수 있다**는 점을 보여준다. 지역난방 설비 사례이므로 발전소 성능을 입증한 것처럼 표현하지 않는다.

## 4. 보안과 통제

[아키텍처](../architecture.md)에 공개 자료만 쓰는 현재 POC와 사내 배포 목표를 구분한다. 목표 구조에서는 원본 추세·정비 기록·검색 인덱스를 현장에 두고, System 2에 범위가 좁은 읽기 전용 도구만 제공한다. OpenShell은 네트워크·파일·자격증명 경계를 강제하고 로컬 NIM으로 추론을 연결한다. 실행 지시는 엔지니어의 승인을 거친다. 실제 차단 실험 전에는 보안 기능을 구현 완료라고 쓰지 않는다.

## 5. 측정할 것

| 단계 | 지표 | 반드시 드러낼 실패 |
| --- | --- | --- |
| System 1 | 고정된 오탐 예산에서 탐지 선행시간·미탐률 | 중복 알람, 센서 오류, 정상 계측과 충돌하는 현장 신고 |
| Nano 선별 | 중요 사건 누락·불필요한 Ultra 호출·지연·비용 | 형식은 맞지만 잘못된 선택, 모델 미응답 |
| System 2 | 근거 있는 다음 점검까지 시간·인용 정확도·도구 사용 | 존재하지 않는 태그, 성급한 원인 확정, 위험한 실행 제안 |
| 통합 | 올바른 식별 시간·엔지니어 검토량·실제 복구 시각 | 탐지만 빨라지고 검토 업무가 늘어남 |
| 경제성 | 실제 출력·판매 가능 조건 아래의 회복 MWh | 가정 시나리오를 실현 절감으로 표시 |

기존 알람/규칙과 단순 검색·요약을 각각 기준선으로 둔다. 제공자 오류는 모델 판단 실패와 분리한다. 지금의 한 사건 POC는 벤치마크 점수가 아니다.

## 6. 다음 실험 순서

1. 공개 시계열을 원래 간격대로 재생해 System 1 규칙 기준선의 탐지 시점·오탐·미탐을 잰다. 현장 신고만으로도 올라가야 하는 사건을 포함한다.
2. 같은 공개 사건에서 규칙과 Nemotron Nano의 선별 판단을 비교한다. 정해둔 조건과 임계값으로만 Ultra를 호출한다.
3. Ultra를 여러 공개 사건에 같은 도구·프롬프트로 실행하고, 인용·태그·점검 순서·판단 보류를 평가한다.
4. Restricted OpenShell에서 허용된 읽기와 차단된 외부 접근을 실제로 시연한다. 그 뒤 측정한 식별 시간을 Economics Bench에 **실험 입력**으로 연결한다.
