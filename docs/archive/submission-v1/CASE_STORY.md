## 한 문장

공개 에너지 설비의 실제 난방 불량 신고를 당시 정보로 재생해, Nemotron이 어떤 계측과 이력을 읽고 무엇을 다음에 확인하자고 했는지, 그리고 그 답변의 출처가 어디서 빠졌는지까지 측정했다.

NVIDIA의 [산업 알람 분석 에이전트 기술 글](https://developer.nvidia.com/blog/building-an-analysis-ai-agent-for-industrial-alarm-management-with-nvidia-nemotron/)은 관련 선행 구조다. 알람 조사 에이전트 자체를 우리 고유 발명으로 주장하지 않는다. 이 제출의 기술적 기여 후보는 공개 사건의 시점·설비·신호 측정 위치·원본 필드를 묶어 검증하고 실패를 평가하는 구현이다. 비교 우위는 아직 입증되지 않았다.

## 현재 정량 증거 — 서로 다른 실험을 합치지 않는다

| 시험 | 관측 수치 | 말할 수 있는 것 | 말할 수 없는 것 |
| --- | --- | --- | --- |
| 기존 사건 재생 | 실제 신고 3건, 모두 같은 서브스테이션; 각 144개 계측; Ultra가 각 2개 읽기 도구 호출 | 공개 사건에서 계측과 과거 기록을 조회해 점검안을 생성했다 | 현장 진단 정확도, 다양한 고장 유형 일반화 |
| 기존 출처 검사 | 실제 3건 중 현재 신고 ID와 계측 ID를 모두 답변에 쓴 사례 1건 | 출처 coverage가 불완전하다 | 나머지 주장 전체가 거짓이라는 결론, 인용의 의미적 타당성 |
| 기존 Nano 선별 | 실제 신고 3건에서 규칙과 같은 조사 결정; 무신고 파생 시험에서 존재하지 않는 서비스 중단 신고를 이유로 생성 | Nano의 증분 이점이 관측되지 않았고 의미 오류가 발생했다 | 검증된 정상 구간 오탐률 |
| 새 System 2 v2 비교 | 서로 다른 서브스테이션 5건, 각 경로 단일 실행. 도메인 Nemotron 경로 2/5, 범용 파일 조사 경로 5/5가 공통 출력 계약을 통과 | 현재 도메인 경로는 계약 준수가 부족하다. 거부된 답변은 표시하지 않았다 | 모델 일반 우열, 점검안의 의미적 정확도. 모델과 실행 하네스가 동시에 다르다 |

새 비교의 5건 중 사례 52는 개발 자료, 사례 60·63은 이전 pilot 노출 사례, 사례 3·13은 v2 실행 전 고른 새 설비 사례다. 독립 전문가 평가는 아직 없다. `reference_checked`는 ID·형식 검사이며 문장의 의미적 지지 검사가 아니다. 새 비교의 모델 요청 시간과 파일 접근 시간도 현장 식별 시간이 아니다.

## 발표에 쓸 화면 구조

1. **사건:** 고객은 열이 없다고 신고했으나, 공급온도는 설정값을 따랐다.
2. **근거 카드:** 144개, 0.31°C, 측정 위치는 2차측 공급, 원본 ID와 시간 구간.
3. **모델 조사 기록:** 실제 읽기 도구와 다음 점검. 저장 trace 재생임을 표시.
4. **검증 카드:** 출처 누락이 발견된 문장을 표시하고, 새 출력 계약이 어떤 정보를 보류하는지 별도 실행 결과로 제시. 새 계약의 통과율을 실제 수치로 표시.
5. **결론:** 구현된 실행, 발견한 오류, 다음 평가를 구분한다. 8시간→30분은 목표로만 둔다.

공식 글의 Figure 1과 같은 일반적인 `근거 수집 → 분석 → 조치` 그림을 전면에 다시 그리지 않는다. 우리 그림은 `설비·시점이 있는 원본 사실 → 모델의 선택 → 주장별 참조 검사 → 표시 또는 보류 → 엔지니어 점검`의 데이터 계약을 보여준다.

## 최종 제출 전에 필요한 검증

- 새 계약의 거부 사례가 단순 JSON 길이 초과인지, 실제 근거 부족인지 구분해 설명한다. 거부 자체를 점검안 품질 향상으로 계산하지 않는다.
- 같은 자료의 고정 요약과 모델 출력을 점검 유용성·불필요한 조치·주장별 근거 지지로 사람이 검토한다. 작성자 검토와 독립 전문가 검토를 구분한다.
- 결과가 변하면 원래 실행과 수정 후 실행을 분리한다. 이미 본 사례를 새 holdout으로 표시하지 않는다.
- PDF·폼·데모 화면의 숫자와 구현 상태를 최종 trace에 맞춰 동기화한다.
