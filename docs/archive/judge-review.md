# 심사위원 관점 검토

YC식 제품·사업 질문과 해커톤의 기술 심사 기준을 적용한 자체 검토이며, 실제 심사위원의 평가가 아니다.

## 판단

문제와 제품 방향은 이해할 수 있다. 현재 증거만으로 상위 10팀의 경쟁력을 확신하기는 어렵다. 시각 개선 다음 우선순위는 한 사건에서 실제 입력 → 도구 호출 → 근거 → 제안이 연결되는 실행과 비교 평가다.

- **누구의 문제인가:** 이상 신고를 받은 운전·정비 엔지니어의 조사 시간. ‘발전소 모든 업무’로 넓히지 않는다.
- **왜 두 모델인가:** Nano는 좁은 사건 선별, Ultra는 근거 종합. 규칙만 사용하는 선별 및 Ultra를 항상 호출하는 기준선과 미탐·오탐·비용·시간을 비교해야 한다.
- **왜 NVIDIA인가:** Nemotron 역할 분리, NeMo Retriever의 추출·임베딩·재정렬, Agent Toolkit의 추적·평가가 구체적인 후보다. 실제 통합한 것과 계획을 구분한다.
- **차별점은 무엇인가:** 일반 문서 요약이 아니라 설비-센서-도면 영역-과거 기록의 연결과, 불확실성을 보존한 다음 점검이다. 아직 자동 도면 인덱싱의 정확도·검색 개선은 측정하지 않았다.
- **8시간 → 30분의 의미:** 8시간은 경제성 시나리오 기준 가정, 30분은 목표다. 실제 사람 평균이나 모델 달성치로 표현하지 않는다. API 응답 시간은 현장 원인 식별 시간과 다르다.
- **현재 POC의 한계:** 지역난방 공개 사건 한 건의 다음 점검 제안이다. 발전소 진단 정확도 검증이 아니며, 현재 trace의 미정의 태그도 남아 있다.
- **주장의 일관성:** ‘원인 식별 30분’을 목표로 삼으면 원인 정답·현장 확인 시간까지 측정해야 한다. ‘다음 점검 제안’만 생성했다면 그 결과를 진단 완료로 계산하지 않는다.

## 발표 흐름

정보가 흩어진 실제 예시 → 두 모델과 인덱스의 역할 → 실행 가능한 공개 사건 → 현재 한계 → 동일 조건 비교로 검증할 30분 목표.

## 랜딩 페이지 자료 경계

공개 PreDist 시계열·신고·과거 조치 발췌는 실제 데이터다. 화면은 원본 CSV·보고서 파일의 스크린샷이 아니라 replay 필드를 재배치한 미리보기다. 공개 원문이 없는 도면·매뉴얼을 실제 사건 자료로 꾸미지 않았다. 발전소 그림은 자체 작성한 개념도이며 물리 시뮬레이터나 디지털 트윈이 아니다. PowerPlantSim은 시각 구성 참고로만 사용했다.
