# Plant Reliability Agent

## 설비 신고를 원본 근거와 다음 점검으로 정리하는 조사 보조

2026 NVIDIA Korea Agentic AI Hackathon · 공개 데이터 POC · 임시 서비스명

발전소 등 에너지 설비의 이상을 조사할 때 엔지니어는 센서가 무엇을 측정하는지, 그 값이 어느 시점의 상태인지, 과거에 어떤 조치가 있었는지 대조한다. 공급온도가 설정값을 따른다는 관측만으로 사용처의 난방이 정상이라고 결론 내릴 수는 없다. 이 프로젝트는 그 판단에 필요한 근거와 확인하지 못한 상태를 함께 보여준다.

현재 구현은 **사건 발생 후 조사하는 System 2**다. 공개 지역난방 자료를 이용해 읽기 전용 조사, 시점별 계측 조회, 근거를 연결한 점검안 생성을 실행했다. 발전소 적용은 목표이며 현장 실증 결과가 아니다. 지속 감시와 24시간 전 예방, Nano 재정렬은 후속 과제다.

## 실제 사건에서 출발한다

PreDist 신고 52는 2016년 12월 12일 15:55의 난방 불량 신고다. 신고 전 24시간에 144개의 계측이 있고, 2차측 공급온도와 설정값의 평균 절대 편차는 약 0.31°C다. 이 구간에서 공급온도가 설정값과 가깝다는 사실과 고객이 열을 받는다는 사실은 다르다.

| 확인 가능한 근거 | 아직 확인할 수 없는 상태 | 엔지니어의 다음 확인 |
|---|---|---|
| 2차측 공급온도와 설정값의 시점별 값 | 방·라디에이터의 실제 온도와 난방 불량 범위 | 영향을 받는 공간과 말단 온도 확인 |
| 1차측 네트워크 계량 유량 | 고객 측 2차 회로의 유량 | 2차측 유량을 측정하고 운전 범위와 비교 |
| 구간 첫 설정값 63.0°C, 마지막 68.6°C | 변경이 자동 제어인지 수동 변경인지 | 시각이 있는 제어기 설정·알람·변경 이력 검토 |

이는 모델 제안의 검토용 설명이며 원인 확정이나 설정 변경 명령이 아니다. 원본은 [PreDist v2](https://zenodo.org/records/19496480), 재생 입력은 [replay-52.json](../data/replay-52.json)이다. 현재 사건의 사후 진단·조치는 입력에서 제외한다. 이전 보고서의 회고적 설명이 당시에 실제로 보였는지는 확인되지 않았다.

## 구현된 조사 방식

1. **사건 경계 설정.** 설비·신고·판단 시점·허용 계측 구간을 고정한다. 공개 자료만 사용한다.
2. **Nemotron Ultra의 근거 조회.** 계측, 이전 사건, 정비 타임라인, 신호 정의, 시점별 온도·설정값, 편차 구간을 읽는 도구 중에서 선택한다. 최대 6회 계획 요청을 허용한다.
3. **구조화된 점검안.** 모델은 점검 종류·이유·선택한 근거 ID를 출력한다. 프로그램이 근거의 합집합을 원본 값과 연결하므로 별도 관측 목록과 참조가 어긋나는 문제를 줄인다.
4. **검증과 사람의 검토.** 허용된 실제 조회 근거인지, 항목 수와 참조가 유효한지 검사한다. 시간·수치 설명의 근거 누락 후보는 별도 경고로 제시한다. 이러한 규칙 검사가 문장 전체의 사실성이나 인과관계를 보증하지는 않는다.

예산 소진 후 최종 생성으로 전환하는 개발 정책은 `bounded_finalize_v2`다. 유효한 조회를 마쳤지만 종료 신호가 없는 경우 예산 소진 사실을 표시하고 최종 생성을 수행한다. 근거가 충분하다고 에이전트가 선언한 것으로 취급하지 않는다. 잘못된 조회나 공급자 실패는 성공으로 변환하지 않는다.

최초 정책의 고정 비교와 수정 확인 실행을 구분한다. [사례 52 수정 확인](../evaluation/cycle4/development/handoff-v2-case52.json)은 6회 읽기 후 27.811초에 관측 12개와 점검 3개를 생성했고, 예산 소진 표시가 남았다. 한 개발 사례의 실행 시간이며 현장 식별 시간이나 일반 성능 수치가 아니다.

## 도메인에 맞춘 설계의 기여

**측정 위치를 구분한다.** 1차측 유량을 2차측 유량으로 취급하거나 공급온도를 실내 온도로 해석하지 않도록 신호 의미와 한계를 도구 계약에 담았다.

**시간 변화에는 시간 근거를 제공한다.** 최소·최댓값과 처음·마지막 값을 구분하고, 같은 시각의 공급온도·설정값을 조회한다. 2°C 편차 구간은 설명용 탐색 기능이며 고장 또는 보호 설정의 기준이 아니다. 결측과 불규칙 간격을 숨기지 않는다.

**점검에서 원본으로 돌아갈 수 있다.** 사실 ID는 출처·필드·시각·값을 보존한다. 모델이 작성한 점검 이유와 원본 관측을 분리해서 보여준다. 참조 존재 검사만으로 충분하지 않으므로 문장별 지지 여부의 내용 평가를 별도로 진행한다.

이것들은 구체적인 구현 기여다. 일반적인 코딩 에이전트보다 조사를 더 잘한다는 주장은 아직 입증하지 않았다.

## 같은 사건을 푼 비교

[Cycle 4 프로토콜](../evaluation/cycle4/PROTOCOL.md)은 사례·자료 해시·출력 조건을 먼저 고정했다. Ultra 경로와 제한된 Claude Code + Sonnet 5 파일 조사 경로가 같은 허용 자료에 접근한다. 기준선은 Read/Glob/Grep과 구조화 출력만 사용한다. 두 경로는 모델과 하네스가 함께 달라 하네스만의 효과를 분리하지 못한다.

| 고정 실행 | Ultra | Sonnet 5 |
|---|---:|---:|
| 개발 사건 52·3: 출력·참조 검사 통과 | 1/2 | 2/2 |
| 신규 설비 사건 29·47: 출력·참조 검사 통과 | 1/2 | 2/2 |
| 전체 | **2/4** | **4/4** |

추가로 양쪽이 모두 결과를 낸 2개 사건의 점검 본문·이유·인용 사실·한계를 익명화해 별도 AI 검토자가 평가했다. 점검 내용 점수는 Ultra 41/48, Sonnet 42/48이며 양쪽 모두 6개 점검 중 3개에서 중요한 인용 누락이 확인됐다. 소수의 성공 출력만을 평가한 점수로 우위를 해석하지 않는다. 현장 전문성은 독립 검증되지 않았다. 첫 평가 패킷에 점검 본문이 빠진 오류를 발견해 원본을 보존하고 수정된 v2로 다시 평가했다. [v2 내용 평가와 방법](../evaluation/readiness/content-review/v2/CONTENT_RESULTS.md)에 이 과정을 공개한다.

Ultra의 실패 2건은 여섯 번의 유효 조회 후 종료 신호를 보낼 요청이 남지 않은 제어 문제였다. 수정 후 개발 결과를 위 표에 합산하지 않는다. 성공한 사례 3에도 점검 이유의 11:00 설명이 인용 사실에 연결되지 않은 문제가 있었다. 결과가 표시된다는 사실과 내용이 옳다는 것은 별개다.

첫 실행의 요청 스냅샷에는 이후 메시지가 들어가는 로깅 오류가 있었다. 응답·도구 결과·시간은 보존했고, 이후 요청은 전송 직전 복사하도록 수정했다. 최초 요청별 문맥을 정확히 재구성하는 용도로 원래 스냅샷을 사용하면 안 된다. [전체 결과와 한계](../evaluation/cycle4/RESULTS.md)에 원본과 수정 범위를 기록했다.

## NVIDIA 기술과 데이터 경계

[NVIDIA NIM의 Nemotron 3 Ultra](https://build.nvidia.com/nvidia/nemotron-3-ultra-550b-a55b)를 도구 선택과 구조화된 점검 생성에 사용한다. 일반 챗봇 답변에 제품 이름을 붙이는 방식이 아니라, 실제 요청·도구 결과·출처 검증을 기록한다. [NeMo Agent Toolkit](https://docs.nvidia.com/nemo/agent-toolkit/latest/index.html) 1.8.0은 최신 읽기 도구 6개를 실행한다. 직접 reader와의 동등성 검사에 더해 [별도 사례 52 실행](../integrations/nat-live-case52.json)에서 모델이 선택한 NAT 조회와 최종 생성을 확인했다. 모델 계획 루프는 Python 코드가 관리한다. 재현 명령은 [통합 문서](../integrations/NAT_LIVE.md)를 기준으로 한다.

OpenShell은 공개 fixture의 허용 읽기·비허용 읽기·쓰기·직접 TCP 차단을 별도 시험했다. 전체 hosted 추론 경로가 OpenShell로 보호된다는 주장은 하지 않는다. API 키와 회사·고객 자료는 제출 패키지에 포함하지 않는다. 로컬 데모 서버는 명시한 공개 파일만 제공한다.

PreDist는 CC BY 4.0 공개 지역난방 자료다. DOE 증기 계통도는 별도 공개 문서 탐색 예시이며 PreDist 설비의 도면이 아니다. 수동 도면 영역 지정을 자동 인덱싱 결과로 제시하지 않는다.

## 산업 가치의 다음 검증

목표 가치는 엔지니어가 다음 점검을 결정할 때 근거를 찾고 대조하는 부담을 줄이는 것이다. 현재 모델 응답 시간은 그 업무 시간의 대리 지표가 될 수 없다.

후속 실험에서는 동일한 신규 사건을 현장 경험자에게 배정하고 기존 자료 탐색과 조사 보조를 비교한다. 순서를 교차 배정하고, 첫 유효 점검안까지의 시간, 중요한 근거 누락, 불필요한 점검, 잘못된 확신을 함께 측정한다. 사전에 기준 점검안을 고정하고 평가자는 방법 이름을 가린다. 현재 8시간에서 30분으로 단축, 발전량 회복, 고장 예방은 측정하지 않았다.

[제출 준비도 기준](../evaluation/readiness/RUBRIC.md)은 별도 내부 기준이며 공식 심사 점수 예측이 아니다. 키 없이 확인할 수 있는 데모, 실행 코드, 결과와 한계를 한 패키지로 제출한다. 자동 제어를 수행하거나 현장 운전 절차를 대체하지 않는다.
