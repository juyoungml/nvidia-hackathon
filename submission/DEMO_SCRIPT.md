# 2분 데모 발표 동선

임시 서비스명: Plant Reliability Agent. 최종 실행 결과가 반영된 PDF와 evaluation 결과를 기준으로 숫자를 말한다.

## 0:00–0:20 문제와 가치

“알람 이후에는 원인을 알아내기 위한 조사가 시작됩니다. 엔지니어는 도면, 추세, 과거 조치를 맞춰 봅니다. 우리는 이 근거 연결을 도와 어디를 왜 확인해야 하는지 전달합니다.”

랜딩의 실제 DOE 도면에서 위치를 선택한다. 이것은 공개 매뉴얼 기반 탐색 예시이며 PreDist 사건의 도면은 아니라고 짧게 밝힌다.

## 0:20–0:40 역할 분리

“작은 모델은 조사할 사건을 선별하고, 큰 모델은 읽기 도구로 근거를 모읍니다. 같은 설비의 기록을 미리 연결해 두는 것이 검색의 기반입니다.”

System 1의 실제 입력 특징과 결정, Ultra 전달 사건을 보여준다. 저장 trace 재생이면 재생이라고 표시하고 실행 중인 척하지 않는다.

## 0:40–1:20 공개 사건 조사

PreDist 사례 52: 'no heat' 신고 → 공급온도/설정값 계측 → 이전 난방곡선 변경 기록 → 실내 온도·유량 미확인 → 다음 점검 제안.

실행 trace에서 출처와 도구 출력을 한 번씩 연다. 근거가 없는 신호·모델 오류가 있으면 숨기지 않고 검증 경고로 설명한다. 사후 진단은 모델 입력에서 제외했다.

## 1:20–1:40 비교와 한계

최종 평가 표에서 실제 사건 수, 구조 검증, 기준선 대비 API 요청·시간을 보여준다. 테스트 통과율을 진단 정확도로 부르지 않는다. Nano 선별 이점이 관측되지 않았다면 그대로 설명한다.

## 1:40–2:00 다음 검증

“8시간에서 30분은 경제성 시나리오의 가정과 목표입니다. 현재 달성한 결과가 아닙니다. 같은 사건과 정보에서 실제 식별 시간을 비교하고, 복구에 이어지는 효과를 측정하겠습니다.”

전체 구조 중 구현·실행된 부분과 계획인 부분을 구분하며 마친다.
