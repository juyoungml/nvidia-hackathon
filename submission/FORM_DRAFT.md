# 온라인 신청서 초안

서비스명: **Plant Reliability Agent** (가칭)
팀명: 제출 전 입력 필요
팀원: 2~5인 구성 및 각 구성원의 개별 신청 확인 필요

## 해결하고자 했던 문제 — 300자 내외

발전소 등 에너지 설비에서 이상 신고가 들어오면 엔지니어는 운전 추세, 설비 문서와 과거 조치를 대조해 다음 점검을 정합니다. 그러나 공급온도가 설정값을 따른다는 사실만으로 사용처에 열이 전달됐는지는 알 수 없습니다. 흩어진 기록을 같은 설비와 시점으로 맞추고, 센서가 측정한 위치와 확인하지 못한 상태를 구분해야 합니다. 이 조사 과정을 돕기 위해 원본 근거와 점검 이유를 함께 보여주는 에이전트를 만들었습니다. 공개 지역난방 설비 사건으로 재현하며, 회사·고객의 비공개 자료를 사용하지 않습니다.

## 서비스 소개 및 주요 기능 — 500자 내외

Plant Reliability Agent는 설비 신고를 받아 계측·과거 이력을 조회하고, 엔지니어가 검토할 다음 점검을 제안합니다. NVIDIA Nemotron Ultra가 읽기 전용 도구를 선택해 시점별 공급온도·설정값과 기록을 대조합니다. 원본 사실 ID로 점검 이유와 출처를 연결하고, 확인할 수 없는 상태 및 검수 경고를 함께 표시합니다. 1차측 유량과 고객 측 유량을 구분하는 등 설비 의미를 도구 계약에 반영했습니다. 공개 PreDist 사건의 실제 실행을 키 없이 탐색하는 데모와 재현 코드를 제공합니다. 같은 자료를 읽는 Claude Code + Sonnet 5와 고정 비교했으며, 4건의 출력·참조 검사에서 Ultra 2건, Sonnet 4건이 통과했습니다. Ultra의 종료 전환 문제는 별도 개발 실행에서 수정 확인했습니다. 이 결과는 진단 정확도가 아니며 비교 우위와 현장 시간 절감은 검증 전입니다.

## 활용한 핵심 기술 및 AI 모델

- NVIDIA hosted NIM, `nvidia/nemotron-3-ultra-550b-a55b`: 실제 도구 선택·근거 조사와 native JSON schema 기반 점검안 생성
- NVIDIA NeMo Agent Toolkit 1.8.0: 공개 읽기 도구 등록. 최신 조사 경로의 적용·검증 범위는 `integrations/NAT_LIVE.md`와 실행 기록 참고
- NVIDIA OpenShell 0.1.2, Docker: 공개 fixture의 허용 읽기·비허용 읽기·쓰기·직접 TCP 차단 별도 시험. 전체 모델 루프 보호 검증은 아님
- Python 3.12+, uv, Ruff, Vulture, unittest; HTML/CSS/JavaScript
- 평가 기준선: 제한된 Claude Code + `claude-sonnet-5`, 동일 허용 자료와 출력 계약
- 공개 자료: PreDist v2 (CC BY 4.0), 별도 DOE 공개 증기 계통도
- Nano 선별은 이전 실험으로 보존. Nano 재정렬, NeMo Retriever 자동 인덱싱, 지속 감시는 후속 후보
